## 二、关键技术决策

### 1. 插件契约直接暴露 WPF `DrawingContext`

源项目的插件可以拿 `QPainter` 自绘灵动岛片段。C# 版的等价选择有两条：

- **方案 A**：抽象层定义 `IIslandCanvas`，与 UI 框架解耦 —— 架构更干净，但插件作者要多写一层适配；
- **方案 B（采用）**：`ClassDailyLand.Plugin.Abstractions` 直接目标 `net10.0-windows` + `UseWPF`，
  自绘扩展点就是 `Action<DrawingContext, Rect>`。

**理由**：与源项目「插件直接用 Qt 绘制」的体验保持一致，插件作者零适配成本。
代价是契约程序集与 WPF 耦合，但本项目本身就是 Windows 专属应用，这个耦合没有实际损失。

### 2. 插件程序集隔离加载

每个插件一个 `AssemblyLoadContext`（`isCollectible: true`），带来两点收益：

- 插件之间的依赖互不干扰，也可以整体卸载；
- **关键是共享契约程序集**：`ClassDailyLand.Core` 与 `ClassDailyLand.Plugin.Abstractions`
  在 `PluginLoadContext.Load` 中返回 `null`，交由默认上下文解析。
  否则插件里看到的 `IPlugin` 与宿主里的 `IPlugin` 会是两个不同类型，
  反射断言必然失败 —— 这是 .NET 插件体系最典型的坑。

### 3. 运行时状态收敛为单一服务

**源项目的一个隐患**：`settings/config.json` 同时存放值日生索引（`StudentOnDuty.py` 写）
和出勤人数（`gui.py` 写）。两个模块各自「读整个文件 → 改自己的字段 → 整体写回」，
一旦交替执行就会把对方的字段抹掉。

**C# 版处理**：`RuntimeConfigService` 独占持有这份文档，
`DutyService` 与 `AttendanceService` 都通过它访问，绝不直接读写文件。
并写了专门的回归测试守住这个行为（`DutyAttendanceTests.SharedConfig`）。

### 4. 星期索引必须转换

- Python `date.weekday()`：**0 = 周一** … 6 = 周日
- .NET `DayOfWeek`：**0 = 周日** … 6 = 周六

`ScheduleService.PyWeekday()` 做了 `((int)DayOfWeek + 6) % 7` 的转换。
**如果不转，整个周末判断会整体错位一天** —— 周六会被当成周五上课。

### 5. Win10 / Win11 能力差异统一收口在 Win32 层

所有平台能力都**先探测、再使用**，能力不足时返回 `false` 而非抛异常：

| 能力 | Windows 10 | Windows 11 | 处理方式 |
|---|---|---|---|
| 深色标题栏 | 1809+ 支持 | 支持 | 直接应用（含属性号 19 回退） |
| Mica 云母 | **不支持** | 支持 | `SupportsMica` 守卫，Win10 静默跳过 |
| 圆角窗口 | **不支持** | 支持 | `SupportsRoundedCorners` 守卫 |

这与源项目 `settings_mica` 的「Win11 生效、Win10 自动忽略」完全对应。

### 6. WPF 窗口材质：为什么没用「一行启用」

.NET 9+ 的 WPF Fluent 主题**会自动给窗口套 Mica**，看似一行搞定。但实测发现两个冲突：

1. 灵动岛 / 副岛是 `AllowsTransparency="True"` 的无边框窗口，自动材质与透明窗口冲突；
2. 官方文档明确：**窗口级 `ThemeMode=None` 并不会排除该窗口，而是「跟随应用主题」**，
   因此无法用 `ThemeMode` 把灵动岛排除在外。

**采用方案**：通过运行时开关
`Switch.System.Windows.Appearance.DisableFluentThemeWindowBackdrop = true`
关闭全局自动材质，改由 `MainWindow.ApplyWindowEffects()` 在 `SourceInitialized` 时
显式应用（含 `CompositionTarget.Background` 透明处理）。
这样能精确控制哪些窗口带材质、以及在 Win10 上如何降级。

## 三、移植过程中发现的工程坑

| # | 现象 | 原因 | 处理 |
|---|---|---|---|
| 1 | `NETSDK1135: SupportedOSPlatformVersion 不能高于 TargetPlatformVersion` | `net10.0-windows` 的 TargetPlatformVersion 默认是 **7.0** | 平台版本写进 TFM：`net10.0-windows10.0.17763.0` |
| 2 | `Application` / `Brushes` / `Color` 二义性报错 | 同时开 `UseWPF` 与 `UseWindowsForms` 时，SDK 把 `System.Drawing`、`System.Windows.Forms` 注入全局 using | `<Using Remove="System.Drawing" />` + `<Using Remove="System.Windows.Forms" />`，Tray 代码改用显式别名 |
| 3 | `Path` / `File` / `Directory` 找不到 | WPF 项目的隐式 using 集合与普通项目不同，**不含 `System.IO`** | 相关文件显式 `using System.IO;` |
| 4 | 元组比较编译失败 | C# 元组**不支持** `<` 等关系运算符（仅支持 `==`/`!=`） | 时间比较改为逐字段先比小时再比分钟 |
| 5 | 配置文件中文被转成 `\uXXXX` | `System.Text.Json` 默认转义非 ASCII | 设置 `JavaScriptEncoder.UnsafeRelaxedJsonEscaping` |
| 6 | 类名与命名空间同名导致 `是命名空间，但此处被当做类型` | 项目 `ClassDailyLand.PluginHost` 内含类 `PluginHost` | 类改名为 `PluginManager`（同时更贴合源项目命名） |
| 7 | `DispatcherTimer.IsActive` 不存在 | WPF 的对应属性叫 `IsEnabled`（与 WinForms 的 `Timer.Enabled` 语义相近，命名不同） | 统一改用 `IsEnabled` |
| 8 | 单文件发布后有 5 个 WPF 原生 DLL 残留在目录里 | WPF 依赖 `wpfgfx_cor3` / `PresentationNative_cor3` / `D3DCompiler_47_cor3` 等原生库，默认不打进单文件 | `<IncludeNativeLibrariesForSelfExtract>true</IncludeNativeLibrariesForSelfExtract>` |
| 9 | 单文件发布报 `IL3000: Assembly.Location 返回空串` | 单文件模式下程序集不从磁盘加载 | 路径解析改为 `AppContext.BaseDirectory` → `Environment.ProcessPath` → 当前目录三级兜底 |

### ⚠️ 最严重的一个：配置被退出流程污染

**现象**：程序运行过一次之后，主窗口再启动就不显示了，而且**用户看不出任何异常**。

**根因**：应用退出时 WPF 会关闭所有窗口并触发 `Window.Closing`。
我最初把「Closing」等同于「用户点了关闭按钮」，于是写入了
`show_main_window = false` 并落盘。下次启动读到 `false`，主窗口被隐藏——
用户只能看到灵动岛和托盘，无法自行恢复。

**修复**：主窗口无标题栏、本就没有关闭按钮，
因此 `Closing` 一律只做「隐藏」且**绝不改动任何配置**。
源项目 `gui.py` 也没有 closeEvent 处理，是移植时我多加的行为。

**教训**：`Closing` 不能用来区分「用户关闭」与「应用退出」。
凡是在 `Closing` 中写配置，都会在退出时产生一次非预期的持久化。

- **关于页**：logo + 名称 + 版本 + 固定文案 + 源码运行保护状态 + 检查更新按钮

  - 去掉自创的「时间」列（源项目是 节次 / 开始 / 结束 + 周一…周日，共 10 列）
  - 补上大标题与用法提示、卡片外框、「共 N 节」与节数过多提醒
  - 行操作从「删除最后一节」改成「删除选中课节」（可点行选中）
  - 补上「导出课表…」「导入课表…」与节数统计，按钮全部移到底部同一行

  - CSV 表头改为源项目的 `CSV_HEADERS`（导出后能原样导入；此前是自创格式，导不回来）
  - 新增**导入预览对话框**（文件类型 / 课表构成 / 附带设置 / 警告 / 导入方式二选一）
  - 导入语义对齐源项目：合并 = 同名自动改名「xx (导入)」；覆盖 = 只替换同名课表；

  - 卡住：视觉层提醒文字只在进入时设置、从不清除 —— 绘制分支永远命中提醒态；
    修复为完整生命周期（停填充 → 动画到提醒条宽度 300 → 到期双清 → 恢复常规）
  - 挤到右边：只动画宽度、`Left` 一步跳终值；修复为 `Left` 与宽度同步动画，
    始终以屏幕中线对称展开（对应源项目 `_animate_to`）
- **触屏支持补全**（用户反馈「触屏控制没了」）
  - 对应源模块 `ui_common.py` 的 `setup_touch_scroll` / `install_touch_scrolling`：
    全局 `ScrollViewer` 样式打开 `PanningMode=Both` + 逐像素滚动（应用级兜底，
    连对话框与下拉列表一并覆盖）；主窗口作业区与设置导航另有
    「按住左键拖动 + 惯性衰减」（参数对齐 `_SCROLL_METRICS`）；
    手动滚动时自动滚动暂停 4 秒（对应 `MANUAL_SCROLL_HOLD_MS`）
- **诊断链路加固**
  - `--capture-delay <秒>`；修复延迟回调重读命令行导致的无穷递归
  - 捕获定时器从 `ApplicationIdle` 改 `Normal`（倒计时 33ms 填充时钟会饿死空闲优先级）
  - 捕获模式下单实例冲突静默退出（原先弹 MessageBox 挂住无人值守运行）
  - 全局异常落盘 `crash-log.txt`；捕获末尾以 8 倍速跑情景演示，
    确定性验证倒计时居中（`screenCenterOffset=0.0`）与提醒恢复
- **修复「课表时间与灵动岛对不上」**（用户实测反馈）
  - 根因：时间偏移模型层缺少范围夹取。源项目 `set_time_offset_seconds` 夹取 ±1800 秒、
    `set_advance_minutes` 夹取 0–60 分钟，移植时漏掉了；一份越界值（诊断脚本遗留的
    15840 秒）便静默生效 —— 编辑器显示原始时间、灵动岛按偏移显示，差了 4 小时 24 分
  - 修复：模型层补上夹取；加载时发现越界值自动归位并回写配置；
    设置页数字框与源项目 `QSpinBox` 一样自带范围，越界值当场夹回
  - 设计语义不变：编辑器永远显示课表原始时间；灵动岛状态机与下拉面板
    显示叠加偏移后的时刻（源项目 `offset_time_str` 的唯一调用点），偏移为 0 时两处一致
